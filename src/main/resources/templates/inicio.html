¿Qué es el proyecto?

El proyecto consiste en desarrollar un visor y editor de procesos empresariales: un Sistema de Gestión de Procesos multiempresa. Cada organización puede registrarse, crear un espacio independiente y administrar usuarios con roles de administrador, editor y solo lectura.

El sistema garantiza autenticación, control de acceso por empresa y separación de la información. Los procesos pertenecen a la empresa y no a usuarios individuales.

Es un desarrollo transversal e incremental durante el semestre. En cada entrega se aplican los temas vistos en clase hasta integrar persistencia, vistas server-side, servicios REST, frontend SPA, pruebas, seguridad y despliegue.

¿Qué debe hacer el sistema?

Gestión de empresas y usuarios

Permite registrar una empresa como entidad independiente, crear el usuario administrador inicial, agregar colaboradores y asignar roles de acceso. El inicio de sesión restringe a cada usuario a la información de su propia empresa.

Gestión de procesos

Permite crear, editar, consultar y eliminar procesos organizacionales, registrando nombre, descripción, categoría y estado: borrador o publicado. También conserva el historial de cambios, permite búsquedas y filtros y usa eliminaciones lógicas para no perder la información histórica.

Modelado del proceso

Un proceso es un diagrama completo. El sistema permite modelar todos sus elementos.

Elemento Qué representa
ActividadUna tarea del proceso.
ArcoLa secuencia del flujo entre actividades y gateways dentro de un mismo pool.
GatewayUn punto de decisión o ramificación: exclusiva, paralela o inclusiva.
Rol de procesoLa función responsable de una actividad, no una persona.
PoolUn participante: la empresa, un cliente, un proveedor o un sistema externo.
LaneUna división interna del pool que agrupa actividades de un mismo rol.
MensajeLa comunicación entre pools: un participante envía y otro recibe.
CorrelaciónEl criterio que indica a qué caso concreto del proceso corresponde un mensaje.

Todos los elementos son obligatorios. Las actividades pertenecen a una lane, los arcos no cruzan pools, los mensajes sí pueden hacerlo y los roles no se eliminan mientras estén en uso.

Ejemplo: proceso de solicitud de vacaciones

Este ejemplo muestra un proceso modelado con todos los elementos del sistema. Sirve como referencia de lo que un usuario puede construir con el editor.

En el diagrama Elemento
El recuadro exterior EmpresaUn pool: el participante dueño del proceso.
Empleado, Jefe inmediato y Talento HumanoLanes asociadas a roles de proceso.
Radicar solicitud, Revisar solicitud y demás tareasActividades.
Las flechas continuasArcos.
El rombo con salidas Sí y NoUn gateway exclusivo.
La flecha punteada al Servicio de correoUn mensaje hacia un participante externo.
Número de solicitudLa clave de correlación del mensaje.

El sistema modela este diagrama, no lo ejecuta.

El usuario dibuja el proceso, lo guarda y lo consulta. No se radica una solicitud real, no se envía un correo y no se descuentan días de vacaciones.

Alcance

El sistema está orientado a la visualización y edición de procesos, no a su ejecución. Los usuarios pueden crear, modificar, consultar y organizar procesos, pero el sistema no dispara flujos automáticos ni ejecuta instancias de proceso.

Todos los elementos del proceso se modelan y se validan, pero ninguno se ejecuta.

El sistema sí debe… El sistema no debe…

Asignar roles funcionales a las actividades por medio de lanes.Usar un motor de reglas o tareas automáticas.

El enfoque es académico: se evalúa la aplicación de conceptos de arquitectura web, separación de responsabilidades, seguridad básica y buenas prácticas de desarrollo.
